# 菠萝猫（boluomao）书源修复总结

> 归档位置：作者私有网盘「书源资料库/站点档案/」目录（本文件）
> 关联交付物：同网盘「调试归档/」下的 `菠萝猫-修复搜索.json`（v14，真机已验证通过）
> 双保险：IMA 知识库「菠萝猫书源修复总结.md」

## 一、站点架构（中继搜索）

- 主站 `boluomao1.com` → 跳转中继页 `rrssk.com/boluomao.html`
- 在中继页 POST `rrssk.com/?action=search` → 服务端 302 跳转 `?action=find&v=..&q=..` → GET 结果页解析列表

## 二、双 cookie 凭证（核心，缺一则 403）

| Cookie | 来源 | 性质 |
|---|---|---|
| `PHPSESSID` | 首次访问中继页 `Set-Cookie` 下发 | 会话标识 |
| `__snc` | `signJs` 响应 `Set-Cookie` 下发 | 一次性搜索凭证 |

- POST 搜索**必须同时携带** `PHPSESSID` + `__snc`，缺任何一个都返回 403「搜索凭证失效」。
- `__snc` 为**一次性**凭证，用完即废，每次搜索需重新获取。

## 三、真因（v14 修复点）

- 中继页**首次加载**拿到的 `_t` 字段，**服务端不认可**（会话尚未预热）。
- 必须在拿到 `PHPSESSID` 后**第二次加载中继页**，才能取到服务端认可的有效 `_t`。
- 浏览器「秒开」正是因为页面加载自然预热了会话，所以 `_t` 天然有效。
- 修复做法：在 searchUrl 里**双加载中继页**，用第二次的 `_t` 去签名和 POST。

## 四、签名算法（每日轮换，结构稳定）

- 常量（从 signJs 用正则按位置提取，不写死）：`K1=6447, K2=34415, KI=7661, KL=18593, XV=290`（`XV=(41*7+3)`）。
- 输入：`__enc(keyword)`（RFC3986 编码后的关键词）。
- 算法每日轮换常量，但**结构稳定**，所以用正则提取比硬编码更稳。

## 五、其他要点

- **WAF**：浏览器 UA 被拦（307 跳验证码），必须带 `curl/8.5.0` 这类 UA；`Referer` 非必需。
- **限流假象**：站点对短时间大量请求做 IP 限流，同样表现为 403，曾一度干扰调试判断（以为是凭证问题，实为被限流）。
- **分页**：从结果页抽取 `v/q` 参数，翻页时复用缓存的 `v/q/cookie`。
- **Legado API 兼容**：用户当前 Legado 构建**只有 `java.ajax` 和 `java.getCookie`**，没有 `java.get`/`java.post`（v13 因此崩溃），v14 仅用这两个 API。

## 六、调试心法

1. 先抓实时 signJs，用正则抽常量，别硬编码。
2. `_t` 无效时第一时间怀疑「会话未预热」，改成双加载。
3. 同样的 403 先排除 IP 限流（冷却后再试），再查 cookie。
4. 只改 `searchUrl` 与 `bookSourceComment` 两字段，其余 19 个字段原封不动。
5. 每搞定一个站点：往 `站点档案/` 加档案，往 `调试归档/` 存 JSON。
