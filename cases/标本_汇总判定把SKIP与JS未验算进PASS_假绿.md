# 判定层回归标本：汇总判定把 SKIP / JS 未验算进 PASS（假绿）

> 归档：2026-11-11，随技能 v1.15.23 并入
> 定位：判定层回归第一号**假绿**反例，与 `cases/标本_吾看书_工具三类失真回归.md`（v1.15.20，**假红**）凑成假红 / 假绿两侧
> 性质：**工具判定的结论与物理事实不符**，不是书源坏

## 一、标本现象

制作 `978小说网书源.json`（m.978xs.com，搜索走 `/api/search` 动态 token POST）交付时，`verify_booksource.py` 汇总判：

- 工具说：`PASS` /「核心字段本地命中 OK」/ exit=0
- 实际是：只抓到 search 一页，explore / bookinfo / toc / content **四区 SKIP**，另有 **9 个 `<js>` 终结字段本地根本不执行**

**为什么这类最危险**：拿不到第二条独立通道的书源作者，看见 `PASS` 会以为全链路验过了。它与 v1.15.20「工具把正常书源判坏三次」是同族的反面——那次是把「没坏」判成「坏」（假红），这次是把「没验全」判成「全绿」（假绿）。

**根因不是抓取，是汇总判定**：把 `PASS / FAIL / 未判定` 三态压成了 `rc 0/1` 二态，缺一个覆盖度维度。中性 SKIP 与本地不执行的 JS 规则被当成「没有失败 → 通过」。

## 二、v1.15.23 的修法（判定口径，不动抓取）

`verify_booksource.py` 汇总段由「看 `test_parse.py` 退出码」改为：

- **四态** `PASS / PARTIAL / UNKNOWN / FAIL`，对应退出码 `0 / 1 / 2 / 3`
- 新增**覆盖度维度**：统计实际有样本的区域数 / 区域总数
- `_collect_js_fields()` 结构化统计「JS 本地未验字段」
- 中性 SKIP 与 JS 未验字段**一律不计入 PASS**
- 删掉「多为硬防护 / Turnstile / 受保护接口」模板化归因，改据实区分 SKIP 原因；顺带修 `tproc` 超时分支未定义崩栈

`PASS` 现在只在「5 区域全有样本且无 JS 本地未验字段」时成立；含 `<js>` 或抓取不全的书源基本落到 `PARTIAL`。**这是修复目标本身，不是回归**——旧版一律 `PASS`。

## 三、判据（改前 / 改后，同一书源）

| 通道 | 改前 | 改后 |
|---|---|---|
| `verify_booksource.py`（978 书源） | `PASS` / exit=0 | `PARTIAL` / exit=2（1/5 区域、9 个 JS 未验字段、4 区 SKIP，归因不再套模板） |
| 四态真值表（Node 换语言独立复算） | — | 7/7：四态与四退出码全可达且互斥 |
| `UNKNOWN` 态（全入口不可达零样本） | — | `UNKNOWN` / exit=3 |

> **证据等级说明**：上述「改前 / 改后」输出由书源侧本地快照与 Node 复算给出，**978 夹具未随 v1.15.23 提交包**（包内 `*978*` 命中 0）。引擎侧合并时可独立复跑的是三道自带自检与 `js_layer --self-test 18/18`，**不是这条 `--source` 因果**。再现此标本需向书源侧索取夹具或另造等价夹具。

## 四、防复发要点

1. **汇总判定必须保留「未判定」态**：二态 `rc 0/1` 无法表达「没验全」。中性跳过、本地不建模的语义要显式进入第三/第四态，不能沉默地并进「通过」。
2. **覆盖度是独立维度**：有样本的入口数 / 总入口数，比单看「有没有报错」更能反映验证完整性。
3. **归因不许套模板**：SKIP 的具体原因要据实区分，统一贴「硬防护」标签等于把未知伪装成已知。
4. **配套纪律**：判据放宽 / 收窄时用「函数级 A/B 同夹具」验证——引用语境降 `[NOTE]` 的同时，凭空假参数仍须报 `[ERROR]`，证明没有外溢假绿（v1.15.23 第三处补修即循此）。
