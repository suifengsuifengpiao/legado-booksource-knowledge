## 二、正文形态：正文是「脚本里的 Base64」，不是 DOM 文本

页面正文容器是 `div#txt`，但**容器里没有可读正文**，只有一组脚本：

```html
<div class="txt" id="txt">
  <p><b>请退出浏览器阅读模式，否则将导致章节内容缺失及无法阅读下一章。</b></p>
  <script>document.writeln(siifrhxc.owcziy('PHA+5LqMb2/kuInlubTlhpzljobljYHkuozmnIjkuInljYHml6XigJzku4rlpKnmmK/lpKflubTkuInljYHvvIzmnaXvvIHmiJHku6zlhYjlubLkuIDmna/jgILigJ08L3A+'))</script>
  ... 共 23 条 ...
  <p><b>请退出浏览器阅读模式，否则将导致章节内容缺失及无法阅读下一章。</b></p>
</div>
```

三个特征，缺一个就会写错规则：

1. **混淆对象/方法名每次请求都变**：本次实测 `siifrhxc.owcziy`，另一次是 `ved.mg`。**任何写死函数名的正则都会在下次请求失效** —— 正则必须吃到「writeln(」之后、引号之前的任意标识符：
   ```js
   /writeln\([^'"]*['"]([A-Za-z0-9+\/=]+)['"]/g
   ```
2. **载荷是标准 Base64 的 HTML 片段**（解出来是 `<p>…</p>`），UTF-8 含 4 字节 emoji，解码必须走 UTF-8 而非 latin1。
3. **容器首尾各一句**「请退出浏览器阅读模式…」，是模板提示、不是正文，需按行过滤。

## 三、四次踩坑与修法（按发生顺序）

### 3.1 `chapterUrl` 行内选项写法错 → 13 章全部回退目录页

**症状**：真机日志「目录 0~12 未获取到 url，使用 baseUrl 替代」，13 章全部打开成目录页，正文为空。

**根因**：规则写成了 `href,{"webView":true,"webWait":3000}` —— Legado 的行内选项必须是 **`##` 分隔**，直接拼在规则后面会被当成选择器的一部分，整串求值为空。

**修法**：改裸 `href`（本站不需要 webView）。行内选项正确形态见 `references/parse-paths.md`：
```xpath
//a/@href##^(.+)$##$1,{"webView":true,"webWait":3000}
```

> 顺带实证：真机 `chapterUrl` 裸 `href` 与 `@href` 等价；本地 JsoupRuleEval 对前导 `@` 有偏差，故统一写 `href`。

### 3.2 `java.base64Decode` 在 3.25 是双参签名

**症状**：正文解析直接抛异常（`正文解析异常: TypeError`）。

**根因**：3.25 的 `base64Decode` 签名是 `(内容, charset)`，单参调用抛异常；旧书源普遍按单参写。

**修法**：改为纯 JS 解码（不依赖 `java.*`，同时规避 `Packages.java` 污染，见 N13）：

```js
var MAP = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/';
function d64(x){
  var t = String(x).replace(/[^A-Za-z0-9+\/]/g, '');
  var buf = 0, bits = 0, bs = [], i, v;
  for(i = 0; i < t.length; i++){
    v = MAP.indexOf(t.charAt(i));
    if(v < 0){ continue; }
    buf = (buf << 6) | v; bits += 6;
    if(bits >= 8){ bits -= 8; bs.push((buf >> bits) & 0xFF); }
  }
  var r = '', k = 0, b0, b1, b2, b3, cp;
  while(k < bs.length){
    b0 = bs[k++];
    if(b0 < 0x80){ r += String.fromCharCode(b0); }
    else if(b0 < 0xE0){ b1 = bs[k++]; r += String.fromCharCode(((b0 & 0x1F) << 6) | (b1 & 0x3F)); }
    else if(b0 < 0xF0){ b1 = bs[k++]; b2 = bs[k++]; r += String.fromCharCode(((b0 & 0x0F) << 12) | ((b1 & 0x3F) << 6) | (b2 & 0x3F)); }
    else { b1 = bs[k++]; b2 = bs[k++]; b3 = bs[k++];
           cp = ((b0 & 0x07) << 18) | ((b1 & 0x3F) << 12) | ((b2 & 0x3F) << 6) | (b3 & 0x3F);
           cp -= 0x10000; r += String.fromCharCode(0xD800 + (cp >> 10), 0xDC00 + (cp & 0x3FF)); }
  }
  return r;
}
```

### 3.3 `@html` 会先删 `<script>` → 真机正文只剩 127 字符

**这是本站最重要的一条**，已升为技能**铁律 27**。

**症状**：真机日志 `诊断[html长度=127,base64块=0]`。本地用 `innerHTML` 验却是 6088 字符全绿。

**根因**：3.25 `AnalyzeByJSoup.getResultLast` 里

```kotlin
"html" -> {
    elements.select("script").remove()   // ← 正文就在 script 里
    elements.select("style").remove()
    textS.add(elements.outerHtml())
}
"all"  -> textS.add(elements.outerHtml())   // 不删
```

用 `@html` 等于**先把正文删干净**，只剩两句提示语——复现长度恰好 127，与真机日志一字不差。

**修法**：正文载体在 `<script>` 里时用 **`@all`**（outerHtml、不删 script/style）。凡「本地全绿、真机全空」且容器长度恰好等于提示语长度的，先查这一条。

### 3.4 章节分页：`hhekgsv` 跨章陷阱

**症状**：第 1 章只读到「…就走开了。」就结束，后面的内容不加载（用户原话「正文下一页没有加载完」）。

**取证**：

| 页 | URL | `<h1>` | 页内 `hhekgsv` |
|---|---|---|---|
| 第1页 | `iytcgscb.html` | 第1章 年夜（第1页） | `→ iytcgscb_1.html`（**第2页**） |
| 第2页 | `iytcgscb_1.html` | 第1章 年夜（第2页） | `→ iytcgsci.html`（**第2章**） |

**分页 URL 规律**：`章id_页码.html`，页码从 1 起（第 1 页无后缀）。`iytcgscb1.html`（无下划线）是 404，`iytcgscb_2.html` 越界会被服务端**钳回第 1 页**（不是 404）。

**陷阱**：`hhekgsv` 语义是「下一段要读的内容」，**末页会直接指向下一章**。照搬它当 `nextContentUrl`，Legado 会一路跟到下一章、再下一章，把整本书拼进第 1 章。

**修法（自包含拼页，不依赖 `nextContentUrl`）**：

```js
// ruleContent.content = id.txt@all<js> ... </js> 内
var url = String(baseUrl).split('#')[0];
var texts = [], g = 0, seen = {};
while(url && g < 8){
  g++;
  if(seen[url]){ break; }            // 防回环
  seen[url] = 1;
  var html;
  if(g === 1){
    html = String(result);           // 第1页先用容器（不依赖网络）
    if(html.indexOf('hhekgsv') < 0){ // 容器不含页头脚本 → 补抓整页
      try { html = String(java.connect(url).body()); } catch(e){ html = String(result); }
    }
  } else {
    try { html = String(java.connect(url).body()); } catch(e){ html = ''; }
  }
  if(!html){ break; }
  var t = blobs(html); if(t){ texts.push(t); }
  var m = html.match(/hhekgsv\s*=\s*['"]([^'"]+)['"]/);
  if(!m){ break; }
  var nx = m[1];
  if(!/_\d+\.html(\?|#|$)/.test(nx)){ break; }   // ★ 只跟随同章下一页，跨章即停
  var nurl = abs(nx);
  if(nurl === url){ break; }
  url = nurl;
}
```

**关键判据**：跨章 URL 一定**不带 `_\d+` 后缀**（章 id 是 `iytcgs**`，分页才加 `_N`）。所以「只接受 `_\d+\.html`」这一条就同时解决了「跟随下一页」和「不越章」两个问题，不需要比较章 id 前缀（`iytcgscb` 与 `iytcgsci` 前 8 字符相同，按前缀比较会误判）。

## 五、已知边界（未验证）

1. **`java.connect` 在真机 content 的 `<js>` 里未实测**。依据是 3.25 dex 存在 `connect(Ljava/lang/String;)Lio/legado/app/help/http/StrResponse;`（见 `legend-js-api.md`）+ Rhino 同引擎模拟。若真机不生效，规则会退化到「只第 1 页」（不会更糟）。
2. **超过 8 页的章节会被上限截断**。目前最长 2 页。
3. **`nextTocUrl: option@value` 未动**：本书 13 章单页目录，未测百章以上多页目录。
4. **搜索限流**：`verify_booksource.py` 用 GET 抓搜索页会拿到空列表并报 `bookList MISS`，是工具抓法差异（站点搜索是 POST），用 POST 真实搜索页复核为 50/50。
