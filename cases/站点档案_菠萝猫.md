# 菠萝猫（Boluomao）书源站点档案

> 关联书源：菠萝猫-修复搜索（v14，真机已验证通过）
> 记录日期：2026-10-05
> 用途：下次遇到同类「中转页 + 一次性签名」架构站点，直接参考，避免重踩坑。

## 一、站点与搜索架构
- 首页 `https://www.boluomao1.com` 只弹窗跳转到中转页 `https://www.rrssk.com/boluomao.html`。
- 真实搜索：POST `https://www.rrssk.com/?action=search`。
- 成功 POST → 302 跳 `https://www.rrssk.com/?action=find&v=..&q=..&page=..` → 再 GET 该结果页（正文含书籍卡片）。
- 详情/目录/正文走 boluomao1.com 同名路径，复用书源现有 ruleBookInfo / ruleToc / ruleContent（本次未改动）。

## 二、必带凭证（缺一即 403）
| 凭证 | 来源 | 性质 |
|---|---|---|
| `PHPSESSID` | 中转页响应 Set-Cookie | 会话 cookie |
| `__snc` | signJs 响应 Set-Cookie | **一次性**会话凭证 |

- `__snc` 是一次性的：同一会话第二次搜索必须重新取中转页 + 重新取 signJs，否则 403「搜索凭证失效」。
- `_t`（中转页 hidden input）也是一次性的，每次搜索需重新取。

## 三、关键坑（本案根因）
> 中转页**第一屏**返回的 `_t` 是**无效**的（会话尚未预热）。
> 必须在拿到 `PHPSESSID` 之后把中转页**再加载一次**，取出的「会话已建立」后的稳定 `_t` 服务端才认。

- 实测：单屏 `_t` → POST 报 403「搜索凭证失效」；双屏 `_t` → 302 跳转结果页。
- 浏览器之所以「秒开」，正是其打开页面的循环自然把会话预热好了（boluomao1.com 弹窗跳转 rrssk.com 本身就是一次额外加载）。

## 四、签名算法
- signJs **每日轮换**常量，从运行时正则按位置顺序提取（结构稳定）：
  - `K1`（初始乘子）、`K2`（每轮 XOR）、`KI`（循环加法常数）、`KL`（循环次数）、`XV = (fp*7+3)`（`fp` 为浏览器探测值，恒 41 → XV=290）。
  - 实测样例：K1=6447, K2=34415, KI=7661, KL=18593, XV=290。
- 签名输入：`__enc(keyword)` = `encodeURIComponent` 后再替换 `!'()*` 为 `%XX`（RFC3986 风格）。
- 密钥：中转页 `_t`。
- `_ts`：当前秒级时间戳，需与 `__snc` 下发时间大致吻合（实测 ±30s 内可过）；不要依赖手机时钟绝对精确。

## 五、WAF / UA
- GoEdge 仅放行 `curl/` 前缀 UA；浏览器 UA 被拦到验证码页（307 → CAPTCHA）。
- 全局 `header` 已设为 `{"User-Agent":"curl/8.5.0"}`；中转页请求也必须带该 UA。

## 六、翻页机制
- 结果页 GET 靠 URL 里的 `v` / `q` + 双 cookie 翻页。
- **POST body 里的 `page` 参数无效**（恒跳 page=1），翻页必须走 `action=find&v=..&q=..&page=N`。

## 七、限流（伪装成凭证失效）
- 站点对短时间大量请求有 IP 频率限制，会返回**同样的 403「搜索凭证失效」**。
- 真机不同 IP 一般不会触发；沙箱/IP 调试时若突然连发 403，先等冷却再判定是逻辑问题还是被限流。

## 八、书源实现要点（Legado）
- 只用经典 API：`java.ajax` + `java.getCookie`。**本机该构建没有 `java.get` / `java.post`**，勿调用（v13 因此直接崩）。
- cookie 串用 `; `（分号 + 空格）分隔；若把空格删掉（`PHPSESSID=x;__snc=y` 无空格）服务端解析不出 `__snc` → 403。
- 结果页 URL 必须**同样带双 cookie**（GET 无 cookie → 404）。
- 每轮 POST 后从结果页正文正则抽 `action=find&v=..&q=..`，翻页复用缓存 `v/q/cookie`。
- 已埋 `[blm]` 日志（`[blm] t=… php=… sp=…` / `[blm] snc=…` / `[blm] post len=…` / `[blm] p5 ok v=…`），失败时可据此定位。

## 九、验证状态
- v14 真机已验证通过：搜索 / 详情 / 目录 / 正文 五项均正常。
- 唯一保留风险：签名算法常量每日轮换依赖 signJs 代码结构稳定；真机设备时钟需基本准确（`_ts` 匹配 `__snc` 时间戳）。
