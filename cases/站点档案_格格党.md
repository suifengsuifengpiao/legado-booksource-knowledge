# 格格党（geged.org）书源站点档案

> 关联书源：格格党 v1.0（2026-10-22 真机一次通过：搜索 / 详情 / 158 章目录全量 / 正文含 `_N` 分页拼接）
> 记录日期：2026-10-22
> 用途：作为**「零防护静态站」的基准样本**。与黄金屋（CF 端点盾 + `?page=N` 分页目录）恰好构成两个极端——同类「无盾 PHP 模板站」直接套本文结构，可跳过全套反爬流程。

## 一、站点与入口架构

- 首页 `https://www.geged.org/`，纯静态 HTML + PHP 模板站，UTF-8，无 JS 渲染正文、无客户端加密。
- **无反爬**：无 CF / 无验证码 / 无签名 / 无字体混淆；全部入口 curl 直连 200（默认 curl UA 也放行，实测）。
- 入口清单：首页 `/`、分类 `/sort/{1-8}/{{page}}/`、详情 `/shu/{id}/`、目录（内嵌详情页）、正文 `/read/{书id}/{章id}.html`。
- 搜索框由 `static/shipsay/common.js` 的 `search()` 动态生成（`document.write` 写表单）——**抓首页 HTML 看不到表单**，必须去 common.js 里找真实提交方式。

## 二、关键坑 ①：搜索是 POST，隐藏字段必带

- 形态：`POST /search/`，字段 `searchkey={{key}}` + **`searchtype=all`**（隐藏 input，服务端按 all/author 分流，不带可能改变结果范围）。
- 书源写法：`searchUrl: "https://www.geged.org/search/,{\"charset\":\"utf-8\",\"method\":\"POST\",\"body\":\"searchkey={{key}}&searchtype=all\"}"`。
- 搜索页无分页（单页结果，站内提示"最多显示 100 条"）。

## 三、关键坑 ②：目录全量内嵌详情页（无需 nextTocUrl）

- 完整目录就在详情页 `#ul_all_chapters li a`，**无分页、无"加载更多"**。
- 实测双样本：111 章（《俯听闻惊风》）与 125 章（《洄天》）均全量在页内，条目数与"目录（N章）"声明数一致。
- 因此 `tocUrl` 不配（Legado 默认用书籍页=详情页再取一次），`chapterList` 直接选 `#ul_all_chapters li a`。
- **目录形态判据（与黄金屋互证）**：详情页里 `#ul_all_chapters` 的 li 数 == 页面上"目录（N章）"声明数 ⇒ 全量内嵌，别写 nextTocUrl；声明数远大于实际条数 ⇒ 分页目录（黄金屋形态，须 `nextTocUrl` JS 页码递增）。

## 四、关键坑 ③：章内分页 `_N` 后缀 + `#next_url` 三态（JS 断链）

- 正文页 `/read/{书id}/{章id}.html`；长章分页 URL 为 `/read/{书id}/{章id}_{p}.html`（如 `154416.html` → `154416_2.html`）。
- `#next_url` 三种指向（实测）：
  - 中间页 → 同章次页（`_N+1`）；
  - 章末页 → **下一章首页**（跨章自动衔接，正文拼接无重复标题——标题在 `.text_title`，不在 `#article` 内）；
  - **全书最后一页 → 详情页 `/shu/{id}/`**（"没有了"）。
- 纯 CSS `nextContentUrl: "#next_url@href"` 会在全书末尾取到详情页 URL（详情页无 `#article` → 正文空 → Legado 停止，虽不致命但不干净）⇒ 用 `<js>` 只认 `/read/` 链接、否则返回空串，彻底断链：
  ```js
  <js>(function(){var h=''+result;var m=h.match(/id="next_url" href="([^"]+)"/);if(m&&m[1].indexOf('/read/')>-1)return m[1];return '';})()</js>
  ```
- `#prev_url` 是"上一页/没有了"（首章首页指向 `/shu/{id}/`），无需配置。

## 五、关键坑 ④：封面 lazy 加载（src 是占位图）

- 搜索 / 发现 / 首页列表：`img` 的 `src` 是 `nocover.jpg` 占位图，**真实封面在 `data-original`** ⇒ 列表页 `coverUrl` 必须取 `img@data-original`（取 src 会得到全站统一的占位图）。
- 详情页封面是直出：`.novel_info_main img@src`。**同一站点两种形态，别套错**。

## 六、关键坑 ⑤：搜索列表与发现列表结构不同（必须两套规则）

| | 搜索页 | 分类 / 首页 |
|---|---|---|
| 列表容器 | `ul.flex > li.searchresult` | `ul.flex > li`（无 searchresult class） |
| 书名 | `h3@text`（h3 内是 `span.hot`，a 在 h3 **父级**，不能写 `h3 a`） | `h2@text`（h2 在 a **内部**，bookUrl 要另取） |
| 书 URL | `tag.a@href`（li 内第一个 a） | `.img_span a@href` |
| 作者 | `tag.p!0@text` 后接 `##^\s*|\s*[0-9][\s\S]*##`（作者行混排"作者\xa0\xa0字数\xa0\xa0日期"） | `.li_bottom a@text` 后接 `##^[^\u4e00-\u9fa5A-Za-z·]+##`（去 `&nbsp;` 前缀） |

> 教训：同一站"搜索"和"发现"的 bookList/name/bookUrl 选择器**不通用**，必须分别取证后再写，不能抄一套。

## 八、翻页机制

- **目录**：无翻页（全量内嵌）。
- **正文**：`_N` 页内分页 + 跨章自动衔接（nextContentUrl）。
- **发现**：`{{page}}`；**越界页钳制**——`/sort/1/999/` 不 404，仍 200 返回（重复末页）内容。发现页翻到尾页后会重复末页内容，属站点特性，非书源问题。
- **搜索**：无翻页（POST 单页）。

## 九、UA / header

- 全局 header（JSON 格式，行格式会被静默丢弃）：`{"User-Agent":"Mozilla/5.0 (Windows NT 10.0; Win64; x64) ... Chrome/120.0.0.0 Safari/537.36","Referer":"https://www.geged.org/"}`。
- 站点对 UA 无差异化（默认 curl UA 也 200），header 按规范配即可。

## 十、书源实现要点（Legado 3.25）

- `content` 用 `#article@html`：`<p>` 段落交给 HtmlFormatter 格式化，保留换行结构；实测 `#article` 内纯净（广告 `tips()` 在容器外），故未加 `##` 净化。
- `nextContentUrl` 的 `<js>` 必须 IIFE 包裹（顶层 return 在 Rhino 报 `invalid return`）。
- `bookUrlPattern` 配 `https://www\.geged\.org/shu/\d+/` 识别本书归属。
- 搜索 POST body 的中文关键词由 Legado 原样替换发送（PHP `$_POST` 可正常接收 UTF-8 字节）——真机实测中文搜索正常；若换站后中文搜索 0 条，再考虑 `<js>` 包 `encodeURI`。

## 十一、验证状态

- **2026-10-22 真机一次通过**：搜索（中文关键词）/ 详情（作者/分类/字数/最新章节/更新时间）/ 目录 158 章全量 / 正文（含 `_N` 分页拼接）。
- 本地核对（BeautifulSoup 复刻 Jsoup CSS 语义）：26 项选择器全部命中。
- 无保留风险（站点零防护）；唯一变数是站点改版（静态模板站改版频率低，改版后按第七节表格逐字段核对即可）。
