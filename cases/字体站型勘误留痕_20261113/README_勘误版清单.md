## 二、11-12 版错在哪

| # | 11-12 版结论 | 勘误版实测 |
|---|---|---|
| 1 | 会话级无限动态字形，静态映射表必失效 | `www.aaawz.cc` 使用**有限 16 套固定字符置换表**轮换，`font.url` 文件名前 12 位即表号 |
| 2 | Legado 3.25 规则层无法自动还原正文 | 规则层 `jsLib` 内置表 + `aaDecode(font.url, 文本)` 逐字查表即可解出通顺正文 |
| 3 | 目录名仍不可救 | 真实 1496 条目录名全部解出，残留乱码特征字符 0 条 |

**根因（错归因）**：11-12 版验的字形轮廓层现象（四份 woff2 轮廓签名全不同、跨会话精确交集 1.18%、家族名随机）都是真的，但属**渲染层**；把它直接等同于「字符置换关系每次会话都变」，并把 `QueryTTF` 三条限制（无 woff2 解码分支 / 精确 HashMap 无容差 / 字形集合可随会话变）外推成「规则层无解」。**这三条只封闭 `java.queryTTF` + `java.replaceFont` 字体 API 通道，不封闭纯字符串置换解码通道**——后者完全不经过字体 API。

一手规范复核：`official-help/ruleHelp.md:180-182`、`references-extra/Legado_3.25_书源编写参考.md:87-89` 只定义三个字体 API，**无任何官方条文说规则层不能做字符串置换解码**。「规则层无法还原」从来不是官方结论，是我方从字体形态自行外推的。

## 三、勘误版新结论（请据此改 §1.5.1）

1. **站型分型表保留**，但「规则层能否还原」一列改为「**未判定，与站型无关**」；`glyph_shape_cjk_identity` 对应 `rule_layer_recoverable=None`。
2. **`QueryTTF` 三条限制保留**，但明确其适用范围为「字体 API 通道」，并删去「三条互相独立 ⇒ 规则层无解」的推论。
3. **§4 实站取证改写**：增补「有限 16 套固定字符置换表」的实站反证与四条独立通道复算；删去「结论：规则层无解 / 目录名仍不可救」。
4. **§6 操作顺序改写**：`glyph_shape_cjk_identity` 后新增一步「另查字符置换通道」，三条任一成立即可在规则层还原，**包含目录名**；只有取证后确无映射线索才写「本规则层无法还原」，且须注明是此站此通道的结论、不是站型推论。
5. **证据等级**：站型判据与 `QueryTTF` 实现边界为 L1（dex 本体 + fontTools 独立复算）；「有限置换表可解码」为**本地实站夹具 L1**（四条独立通道），**未做真机复验**，不写「已修复」。

## 五、未验边界（如实）

- 16 套表是否覆盖站点全部下发字体**未证**（本地仅 5 个 key，全命中）；别家 `aaDecode` 对无表 key 原样返回乱码，自带降级兜底。
- `ruleSearch` / `ruleBookInfo` 层未用真实响应端到端复跑；该站发现页不启用。
- C1/C2 用 `new Function` 包裹取返回值，是 harness 近似，≠ 真机 Rhino 绑定；规则原文末句为裸表达式，与 3.25 表达式上下文一致，但**未做真机复验**。
- 完整书源能否在真机 3.25 导入即用**未验**；证据等级为本地实站夹具 L1。
- 字体样本与复算脚本**未随包**（会话级样本无法固化），文内 §4.4 给了自包含复算片段。
