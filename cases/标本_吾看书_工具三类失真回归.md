# 标本：吾看书 —— 工具链三类失真的一号回归反例

> 归档日期：2026-11-03
> 来源：书源侧 v1.15.20 提交（`书源侧提交_20261103/`），引擎侧独立复现后归档
> 适用版本：修复于 v1.15.20；v1.15.19 及更早版本在本标本上会误判

## 一、为什么把它列为一号反例

同一份在 Legado 3.25 真机上**正常工作**的书源，被检测工具判成**三处坏**。三类失真（假阳 / 假阴 / 未建模）在同一份标本上同时出现，且每一类都指向同一个根因：

> **工具的解析层只建模了 XPath，而 3.25 的默认解析引擎是 JSOUP。**

默认引擎不建模，等于默认把大多数静态站判坏。这类失真是下游最危险的一类——用户拿不到第二条独立通道，只能相信工具的红字，于是去改本来没坏的书源。

## 二、标本特征

| 特征 | 值 | 触发的失真类型 |
|---|---|---|
| `ruleExplore` | `{}`（空对象） | 假阳：发现页每个入口各报一条「缺字段」 |
| `exploreUrl` | 18 条入口 | 放大假阳条数（18 × 3 = 54 条 ERROR） |
| `ruleBookUrl` | `//a/@href` 形态 | 假阴：lxml 的 `//` 从文档根重搜，取到 logo |
| `ruleTocUrl` | `text.查看更多章节@href` | 未建模：JSOUP 默认规则，lxml 必抛异常 |
| `@css:` 前缀 | 小写写法 | 假阴：被当 JSOUP 规则求值，取空 |

## 三、三类失真逐个对照（引擎侧实跑数据）

### 1. 假阳：`ruleExplore: {}` 未建模"回退 ruleSearch"

3.25 语义：`ruleExplore` 为空对象或缺失时，发现页回退 `ruleSearch` 的解析规则。

| 版本 | 判定 |
|---|---|
| v1.15.19 | 每个入口各报「缺字段: bookList / name / bookUrl」 |
| v1.15.20 | 假 ERROR 全部消失 |

引擎侧用同形态源（笔迷读，`ruleExplore: {}`）复现：旧版报 `发现解析(ruleExplore #12/#13) 缺字段` 共多条，新版为 0。

### 2. 假阴：`//a/@href` 取到 logo 首页

列表页首个 `<a>` 是 logo（`https://www.wukanshu.cc/`），书籍链接在列表条目内。lxml 的 `//` 是**文档根绝对路径**，不是相对当前节点。

引擎侧离线对照（列表定位 `//div[@class='bookbox']//h4`）：

| 书 URL 规则 | v1.15.19 | v1.15.20 |
|---|---|---|
| `//a/@href` | `https://www.wukanshu.cc/`（logo） | `/book/519/` ✅ |
| `/a/@href` | `None` | `/book/519/` ✅ |
| `@href` | `None` | `None`（裸属性在 h4 节点上无此属性，符合预期） |

修法：`//x`→`.//x`、`/x`→`./x`，把求值锚定在列表首个节点上。

### 3. 未建模：JSOUP 默认规则恒 MISS

`tocUrl` 写成 `text.查看更多章节@href`（3.25 默认引擎的 JSOUP 规则），旧版 `first_match` 只认裸属性与 XPath，lxml 对这串必抛异常，于是 `tocUrl` 恒 `None`，目录 / 正文连锁 SKIP。

引擎侧离线对照（HTML 含 `<a class="more" href="/book/519/">查看更多章节</a>`）：

| 版本 | `first_match('text.查看更多章节@href')` |
|---|---|
| v1.15.19 | `None` |
| v1.15.20 | `/book/519/` ✅ |

修法：`first_match` 增加 `_jsoup_first()` 兜底，复用 `test_parse.eval_rule_jsoup`，**仅对非 XPath 形态生效**（不以 `/` 或 `@XPath:` 开头）。这条边界是必要的：写错的 XPath 若拿 CSS 语义再求一次，会把"取空"变成"命中错误节点"的假阳性，比 MISS 更难发现。

### 4. 附带：`@css:` 大小写

反编译 `AnalyzeByJSoup.kt:484` 为 `startsWith("@CSS:", true)`——大小写不敏感。

| 版本 | `detect_mode('@css:.content')` |
|---|---|
| v1.15.19 | `jsoup`（被当默认引擎规则，取空） |
| v1.15.20 | `css` ✅ |

## 四、回归用法

拿本标本做回归时，三条断言都要过：

1. `validate_booksource.py 吾看书.json` → 发现页相关 `ERROR=0`（假阳清零）
2. `verify_booksource.py 吾看书.json` → `bookinfo` 抓到的 URL 是 `/book/<id>/` 而非站点首页（假阴清零）
3. `verify_booksource.py` → `tocUrl` 有值而非 MISS（未建模补齐）

## 五、已知边界（做回归时别误判成新 bug）

1. 吾看书目录页对沙盒 IP 返回 403（真实浏览器实跑亦 403），`toc` / `content` 取不到有效样本；`tocUrl` 只验到"规则求值出值"，没验到"该地址在站点有效"。
2. `##$##替换` 在 `test_parse` 内按"整串置为替换串"实现，属历史假设，未在 3.25 dex 复验。若真机实为"行尾锚点插入"，`tocUrl` 一类规则会差一段。
3. 该源部分字段用 `<js>` 动态拼 URL，`verify_booksource.py` 不执行 JS，相关字段仍属既有边界。

## 六、根因沉淀

> 工具判错一次，下游会拿错误结论去改正常书源——**比没有工具更坏**。

凡是"默认引擎行为"，工具必须建模，不能只建模显式写法（XPath）。不建模时的正确做法是输出「需真机验证」，而不是输出「书源坏了」。
