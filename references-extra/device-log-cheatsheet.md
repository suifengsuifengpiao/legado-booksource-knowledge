## 一、两种调试入口（同一套日志）

| 入口 | 怎么进 | 适用 |
|---|---|---|
| **App 内调试界面** | 书源管理 → 选中书源 → 🐞（或编辑界面「调试」）→ 输入关键字/URL | 零成本，用户自己能跑；输出可长按复制/截图 |
| **Web 调试桥** | 设置 → 网络 → Web 服务（默认端口 1122）→ `scripts/legado_debug_bridge.py` 经 WebSocket `/bookSourceDebug` 推书源 + 收日志 | 有电脑且同局域网，可落盘整段日志 |

> 两者走的是**同一条 `model/webBook/x0`（=WebBook 门面）→ `model/n0.f()` 调试引擎**代码路径，
> 所以调试通过 = 该链路在真机可用，调试失败的根因就是线上失败的根因。

## 二、调试命令语法（输入什么 = 跑哪一步）

> 以下为 App 内调试框直接输入的写法；Web 桥用 `--key` 传同样的内容（见 device-diagnosis.md 的判定顺序表）。

| 输入形态 | 触发阶段 | 示例（来自内置 debugHelp.md） |
|---|---|---|
| 普通关键字 | **搜索**（跑全链：搜索→详情→目录→正文） | `系统` |
| `http(s)://` 开头的 URL | **详情页**（从该详情页开始） | `https://m.qidian.com/book/1015609210` |
| `标题::发现URL` | **只调发现页** | `月票榜::https://www.qidian.com/rank/yuepiao?page={{page}}` |
| `++` 前缀 + URL | **只调目录页** | `++https://www.zhaishuyuan.com/read/30394` |
| `--` 前缀 + URL | **只调正文页** | `--https://www.zhaishuyuan.com/chapter/30394/20940996` |

写错形态就跑错阶段——调试框不会报错，只是"调试了错误的页面"。

## 三、日志符号表（必背）

日志前缀字符集由 `t6/i.java` 正则锁定为 `⇒ ◇ ┌ └ ≡`（外加 `︾` 在 `n0` 里单独使用）。逐符号含义：

| 符号 | 含义 | 典型原文（n0.java / webBook 链路） | 判读 |
|---|---|---|---|
| `⇒` | **开始访问 / 发起请求** | `⇒开始访问详情页:`、`⇒开始搜索关键字:`、`⇒开始访目录页:`、`⇒开始访正文页:` | 看到它 = 已构造 URL 并发起网络请求；之后没紧跟 `︾` 多半是网络/超时/被墙 |
| `︾` | **开始解析**（对拿到的源码执行规则） | `︾开始解析搜索页`、`︾开始解析详情页`、`︾开始解析正文页` | 看到它 = 已拿到响应并进入规则求值；之后没"解析完成" = 选择器/JS 报错 |
| `≡` | **信息 / 检测**（不阻断，提示性） | `≡已获取目录链接,跳过详情页`、`≡检测到重定向(`（RSS 链路） | 提示类；`≡检测到重定向` 在 webBook 链路少见，多在 RSS |
| `┌ … └ …` | **配对：重定向前/后地址对**（或 RSS 各字段取值起止） | `┌重定向后地址` → `└<实际URL>`；`┌获取正文下一页链接` → `└<链接列表>` | `┌` 是"标题行"、`└` 紧跟的是"值"。重定向看这对：┌ 写期望值、└ 写实际落到的地址，不一致就是被服务端跳走 |
| `◇` | **信息分隔 / 其它提示**（同属合法前缀集） | （APK 帮助未单列用法，属辅助标记） | 出现即正常日志，无需特殊处理 |

> `┌/└` 是**成对**出现的：先 `┌<标题>` 再 `└<值>`。单看一个没意义，要找它的配对行。

## 四、用日志定位"沙盒绿、真机空"的三类死局

| 现象（日志里看到） | 根因 | 对策 |
|---|---|---|
| 一直 `⇒` 反复、偶有 `≡`，最终 `TimeoutCancellationException: 60000ms`，webJs 连续 `null` | **about:blank 死局**：CookieStore 回写 → 下次注入 → 命中限流 → `location.href=about:blank` → 协程吃满 60s | 见 pitfalls.md 的「双清闭环」（铁律 16）；或优先用顶层 `并发率` 从源头限速（见 booksource-schema.md） |
| `⇒` 后有很长停顿，无 `︾`，最终超时 | **网络慢 / WebView 没加载完**：`webWait` 给太短或站点本身慢 | 调大 `webWait`；或确认是否真走了 webView |
| `︾` 出现但无"解析完成"，或 `︾` 后报错 | **规则/JS 报错**：选择器不匹配、JS 抛异常、`return null` 死循环 | 在对应规则插 `<js>java.log(变量);</js>` 看中间值（debug 纪律），别盲改选择器 |
| 正常出现 `⇒ → ︾ → 解析完成` | **链路通过** | 无需处理；导出该阶段结果核对字段 |

**成功标志**：日志末尾出现「**解析完成**」即该阶段真机可用（device-diagnosis.md 的 Web 桥以 exit 0 = 全部阶段"解析完成"判定）。

## 五、调试纪律（配合 `java.log`）

真机调试命中异常字段时，在对应规则里插 `<js>java.log(结果变量);</js>` 打印中间值，再连桥/看日志，**禁止盲改选择器**。
（日志对象方法见 [legend-js-api.md](legend-js-api.md)。）
