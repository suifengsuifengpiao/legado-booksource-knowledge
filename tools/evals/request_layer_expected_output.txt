# v1.15.15 变更（保留供对照）：① 控制字符改两步走（{{...}} 占位 + 字符串内控制字符转义后再解），

# v1.15.17 变更（本版）：
#   ① **R5 只看 path**：`_r5_volatile` 先 `split("?",1)[0]`，查询串里的 4+ 位数字不再报。
#      后果是**口径变化不是修复**：b10a / b10b / c4（查询串带长数字）由阻断转通过，末三条即这三格。
#      不用 `urlsplit(url).path` —— 相对路径（`/list/2026/?cid=5`）下它返回空 path，会漏判。
#   ② **NOTE 路径改按复解出的 arr 逐条判**：不再从原文 `https?://` 粗提再按 11 个结构字符切碎。
#      旧法在两个方向上错：该报的不报（B8b：加个裸换行就只报半段）、不该报的报（D3b：title 里的
#      假 URL 被当 URL 判）。现在两条路径共用同一个 `_r5_volatile`、同一种 `[JSON[i]]「title」` 归属格式。
#   ③ 归属自证：`d3_url_volatile_newline`（title 干净、url 易失）必须报 `[JSON[0]]「玄幻」`；
#      `d3b_title_url_newline`（title 里放假 URL、url 干净）必须不报。两条一正一反互相钉住。
#   ④ 相对路径反例：`a3_relative_path_query`（exploreUrl 写 `/list/2026/?cid=5`）必须报 `'2026'`——
#      R5 判「原串 path 里有没有长数字」，与相对/绝对无关。这条同时钉住「不许改用 urlsplit().path」的
#      正确理由：普通相对路径两者等价（M2 实测 urlsplit 也拿得到 path），只有 `//` 开头的协议相对路径会漏。
#   ⑤ 多条目归属：`a5_multi_item_mixed`（第 0 项干净、第 1 项易失+裸换行）必须只报 `[JSON[1]]「武」`，
#      不报到第 0 项、也不因存在干净项而整体沉默。
