# `precheck_public_push.sh` 启用说明（引擎侧，2026-11-13）

> **状态：已启用。** 运行件位于引擎侧 `/root/.codebuddy/scripts/precheck_public_push.sh`；知识库 `tools/precheck_public_push.sh` 为书源侧交付的归档原件（判据基准）。门禁以**显式调用**方式工作，不挂 git hook、不改动任何既有推送机制。

## 来历

书源侧 `书源知识库补充材料_20261112.zip` 的 `tools_脚本级/precheck_public_push.sh`（v1.15.24 修复版）。该脚本**在技能目录之外**，历史约定不随技能包分发：它是「公开仓推送前脱敏自检」，用来防止 Gitee 长期令牌 / 记忆层文件 / 沙箱内部标识被推上公开仓。

v1.15.24 新增**第 6 项「归档包内脱敏」**：此前 1~5 项的 `grep -rI` 只扫平铺文本，待推送区里的 `.zip/.tar.gz` 是二进制、被 `grep -I` 整包跳过——包内若含令牌明文，门禁四项全绿 `exit=0`（假阴性，比假红更危险）。第 6 项把包解到临时目录，用同一套判据补扫，只做文本比对、不执行包内文件，>50MB 显式告警跳过。

## 六项判据

| 项 | 判据 | 级别 |
|---|---|---|
| 1 | 令牌明文（token 段 + 整行 URL 两类敏感串） | 硬失败 |
| 2 | 常见凭证模式（`password`/`access_token`/私钥头/`ghp_`） | 硬失败 |
| 3 | 记忆层文件 `SOUL.md`/`MEMORY.md` | 告警不阻断（需用户同意） |
| 4 | 沙箱内部标识（本机 hostname / 本会话 UUID 前缀） | 硬失败 |
| 5 | 版本同步（仅对待推送目录是技能包时生效） | 硬失败 |
| 6 | 归档包内脱敏（解包补扫 1~4 项判据，不执行包内文件） | 硬失败 |

退出码：`0` 通过 / `1` 检出问题 / `2` 用法错误。

## 静态审查结论（只读）

对脚本全文逐行审查 + `bash -n` 语法检查通过。可疑模式命中全部落在**脱敏检查本身**：

| 命中 | 实际用途 |
|---|---|
| `grep ... "$token"` / 凭证正则 `password\|access_token\|ghp_` | 第 1/2 项判据，检查待推送区有无令牌/凭证明文 |
| `hostname` / 会话 UUID 前缀 | 第 4 项判据，检查有无沙箱内部标识 |
| `unzip -q -o` / `tar -xzf` | 第 6 项把包解到 `mktemp` 临时目录做文本比对，**不执行包内文件** |
| `rm -rf "$ARCHIVE_TMP"` | 仅 `trap cleanup_archive_tmp EXIT` 清理自己 `mktemp` 出来的临时目录 |
| `~/.git-credentials` 读取 | 第 1 项凭据来源，仅本地解析出敏感串用于比对，不回显、不外发 |

**未发现**：提示词注入、联网下载（`curl`/`wget`）、授权/凭据外发、`eval`/`bash -c` 执行包内文件、`chmod +x`/`source` 等环境修改。判定为安全的只读门禁。

## 引擎侧启用适配

归档原件按书源侧环境写成，直接照搬会在引擎侧产生两处失真，故运行件做了 4 处最小适配（差异面经 `diff -u` 逐段核对，仅此 4 处）：

1. **凭据来源**：归档件读 `TOKEN_FILE=/root/.codebuddy/.credentials/gitee_token`（纯令牌文件），引擎侧该文件不存在，实跑会打印「跳过第 1 项」——最关键的令牌检查根本没执行（假阴性）。引擎侧真实凭据在 `~/.git-credentials`，为 URL 形态 `https://user:token@host`。运行件改为从 `~/.git-credentials` 解析出 **token 段** 与 **整行 URL** 两类敏感串，任一命中即判失败；**不新建任何明文令牌文件、不回显令牌值**。可由 `PRECHECK_CRED_FILE` 覆盖凭据路径。
2. **凭据源读不到不静默放行**：无任何可用凭据源时判 `fail=1` 并明示「第 1 项无法执行」，不再报「未检出/通过」。
3. **第 1/6a 项遍历敏感串**：由单值 `grep` 改为对敏感串数组逐个比对，命中只打印文件路径、不打印令牌值。
4. **会话 UUID 举例示意化**：归档件注释里把真实会话 UUID 前缀（形如 `<会话UUID前8位>`）写进了公开仓，正是第 4 项要防的自我违背——启用后扫知识库会命中脚本自身、恒 `exit=1` 假红。归档件与运行件该行注释均改为 `.../<会话UUID前8位>-.../...` 示意占位，教学含义不变。

其余 1~6 项判据与归档原件逐字相同，未改动判据逻辑。

## 调用时机与回滚

- **调用时机**：每次向公开仓（`gitee` / `gitee-public`）执行 `git push` 前，对待推送目录显式跑一次 `precheck_public_push.sh <目录>`，`exit≠0` 时先处置再推。GitHub 镜像因令牌过期暂不推送，恢复后同样适用。
- **不自动拦截**：未挂 git hook、未改 `~/.gitconfig`、未改任何推送脚本；是否调用由推送动作的执行者负责。
- **回滚**：删除 `/root/.codebuddy/scripts/precheck_public_push.sh` 即完全回到启用前状态（无既有门禁被覆盖，属首次安装）。

## 与发布线的关系

本脚本**不在** `legado-booksource-debug_v1.15.25.skill` 技能包内（符合「不随技能包分发」的历史约定），也不参与 `md5_sync_check.py` 的 `.py` 同源比对（门禁只扫 `.py`）。它是知识库侧的独立归档材料 + 引擎侧的运行件，二者判据基准一致。
